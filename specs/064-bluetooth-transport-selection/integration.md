## Shared Contract and Ownership

The **parent integration owner** is the single accountable coordinator for shared-file sequencing, app composition and milestone records. This is a work role for the implementation driver, not a new module or service. Record the actual assignee and current task handoff in the parent implementation evidence before concurrent implementation begins. Only one worker edits each shared file at a time.

| Surface | Implementation owner | Coordination rule |
|---|---|---|
| Raw CTAP operation boundary, BLE GATT/framing, Nordic advertising, BLE buffers and security | BLE owner | BLE:T004–T019 and T030–T033 own transport behavior. Selection consumes the real implementation; it does not recreate it |
| Fido2Transport and neutral state | BLE owner, reviewed by parent integration owner | BLE:T010 updates existing Classic/consumers; BLE:T018 implements the new BLE contract. Selection:T012 verifies and integrates that same boundary, rather than designing a second interface |
| Fido2TransportService and Fido2HomeViewModel | BLE owner for BLE lifecycle/state; parent integration owner for selected-handle wiring | BLE:T026–T027/T034 establish behavior; Selection:T015/T034 wire and verify the frozen handle. Reconcile the edits in one ordered integration increment |
| ChimaliApplication / app composition and Fido2Module binding changes | Parent integration owner | Selection:T013–T015 and BLE:T028 are one coordinated integration, not two bindings or competing factories. Use the actual app file path in the task lists |
| ProcessTransportSelection, preference persistence and settings UI | Selection owner | Selection:T005–T011 and its user stories own process choice and settings. BLE observes the selected run and does not create a second selector |
| Canonical BRD/TRD IDs, evidence registers and shared rules | Parent integration owner coordinates both feature owners | Reserve IDs once, distinguish local feature IDs, preserve existing IDs and annotations, and link evidence into both scopes where applicable |

The selected dependency remains Nordic Kotlin BLE Library advertiser 1.3.1 with the narrow public Android GATT supplement described in the [BLE plan](../064-fido-ble-transport/plan.md). Dependency failure does not authorize another library, a hidden API, a security downgrade or a toolchain change.

## Handoff Gates

1. **Isolated BLE review:** Selection:T002 reviews a named source/tree revision and the isolated contract after BLE:T018–T019. It does not require BLE:T020/T023 physical results. Record remaining implementation and evidence limits; do not label a partial component accepted.
2. **Composition:** Selection:T012–T015 and BLE:T028 follow that review and the parent gate implementation. Run Selection:T016 before dependent integrated progression. Do not bypass the gate with a temporary production binding to obtain physical evidence.
3. **BLE acceptance:** BLE:T020/T023/T035 use the composed application; BLE:T036 assesses the parent gate/handle boundary, not the complete selection settings/switch acceptance matrix. Finish all component obligations before marking BLE complete.
4. **Parent acceptance:** Selection:T022/T027/T031/T035/T041 assess the full parent behavior with the real accepted BLE component. Preparatory parent implementation or an isolated fake does not establish the BLE-default feature's acceptance.

Keep BLE evidence in its implementation-evidence.md and parent evidence in the parent's implementation-evidence.md, created by their respective T001 tasks. The parent record links milestones, assignee, component revision and handoff outcomes. Avoid a third evidence register in this document.
