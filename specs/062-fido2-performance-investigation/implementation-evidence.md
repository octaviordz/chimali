## T027 lifecycle terminal-ordering fix (2026-10-31)

**Problem confirmed by probe 02:** The `PerformanceTrace.section` finally block called `recordTerminal()` immediately after `withContext(lifecycle) { block() }` returned. In the Kotlin coroutines threading model, `restoreThreadContext` (which calls `endSegment`) for the last active segment can execute on its dispatcher thread after the outer coroutine's continuation resumes — producing the probe 02 symptom of `valid=false complete=false` with a suspend record appearing after terminal in the log.

**Fix:** `LookupTraceCorrelation.recordTerminal` now accepts an optional `onTerminalReady: (() -> Unit)?` callback and returns a `TerminalResult` tri-state instead of `Boolean`:

- `IMMEDIATE` — no active segments at call time; caller emits terminal inline.
- `DEFERRED` — active segments remain; callback stored and invoked by the last `endSegment` that drains `activeSegments` to zero. Terminal flag is set atomically; any subsequent `endSegment` drain invokes the callback exactly once via `AtomicReference.getAndSet(null)`. A re-check after `AtomicReference.set` guards the race where `endSegment` drains between the `isEmpty` check and the `set`.
- `REJECTED` — no lookup mapping or terminal already set; caller emits `valid=false`.

`PerformanceTrace.section` passes a deferred callback that emits `AndroidLookupTraceEventSink.terminal` with `valid=true`. On `IMMEDIATE` it emits inline. On `REJECTED` it emits `valid=false`. On `DEFERRED` it suppresses inline emission. This preserves the measured lookup boundary, cancellation, and exception behavior exactly; no extra suspension or blocking is added.

`LookupTraceCorrelation.endSegment` now checks `pendingTerminalCallback` after draining `activeSegments`. `Fido2OperationTraceContext` and `CoroutineTraceLifecycle` are unchanged.

**Verification:** `:feature:fido2:testAndroidHostTest --tests com.chimali.fido2.util.performance.CoroutineTraceLifecycleTest` — **6/6 passed, 0 failures, 0 errors, 0 skipped** (up from 3 tests; added: deferred callback when segments remain, immediate path when segments already drained, multi-segment deferred fires on last close). Ktlint passed for both `ktlintAndroidMainSourceSetCheck` and `ktlintAndroidHostTestSourceSetCheck`. No regression to existing cancellation, dispatcher-change, missing/duplicate-mapping, or duplicate-terminal cases.

**Remaining T027 state:** Host lifecycle validation now covers the terminal-ordering race. Device-level validation (a complete production-path probe with `valid=true complete=true` terminal in the retained log) remains outstanding and is the next step before T028 can proceed.
