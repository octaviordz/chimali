# SensitiveCredentialText active conversion review

- **Requirements:** FR-003/004/010; NFR-SEC-041; TR-AUTH-031; T012.
- **Revision:** Dirty exploratory worktree; current revision identity is tracked in `source-inventory.json` and `assessment.md`.
- **Scope:** `SensitiveCredentialText` construction, UTF-8 conversion, caller-owned character copies, RP-ID text boundaries, and current production call sites.
- **Observed behavior:** `fromUtf8Bytes` and `fromUtf8Range` clear their decoder `CharBuffer` backing arrays in `finally`; `toUtf8Bytes` clears its encoder backing array in `finally` and returns a separate caller-owned byte array. `copyCharacters` likewise returns a separate caller-owned array. These returned owners remain the caller's responsibility.
- **Immutable boundary:** `toBoundaryString` creates an immutable `String`. The unused `toRpId` conversion and `PublicKeyCredentialRpEntity.id` compatibility getter have been removed; `GetAssertionOptions.rpId` was replaced by the explicitly named `rpIdForTextBoundary()` at its active prompt and notification text consumers. `GetAssertionUseCase` continues to borrow `rpIdText` for repository filtering. Required UI/system-authentication and transport-notification text still crosses immutable platform boundaries.
- **Disposition:** The API cleanup removes the intermediate immutable `RpId` wrapper and unused getter; it does not remove the actual String needed by UI/platform surfaces. The accessor reads the current mutable owner contents and observes zeros after owner erasure in a focused regression. `GetAssertionOptionsTest` passes 5/5; the complete FIDO Android host suite passes 1,315 tests across 172 XML reports with zero failures/errors/skips, and `:feature:fido2:ktlintCheck` passes. The prompt/notification caller and platform retain separate non-erasable String copies whose lifetimes remain unverified. External consumers outside this repository were not assessed.
- **Limitations:** This source review does not establish platform/provider copies, UI/system prompt retention, external API usage, garbage collection, generated SQL/SQLite/WAL lifecycle, or heap roots. The generated-row signature review remains separately recorded in `sql-delight-generated-row-signatures.md`. T012, T005, T006, and T015 remain open.
- **Date:** 2026-11-17 (updated after compatibility conversion removal).
- **Status:** The bounded conversion/API regression is Verified on host. Platform/runtime/heap and downstream immutable borrower behavior remain Unverified.
