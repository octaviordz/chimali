# Credential repository concurrent cold-flow ownership

- **Requirements:** FR-003/004/010/015; NFR-SEC-041; TR-AUTH-031; SEC065-FIDO-OWNER-004; T006/T012.
- **Scope:** `CredentialRepositoryReadOperations.searchCredentials`, borrowed `SensitiveCredentialText` query lifetime, two concurrently collected cold flows, cancellation before an emission is accepted, and independent `PasskeyCredential` owners.
- **Revision:** Dirty exploratory worktree based on `78812e4d0a2d4ff422e03cd71611d6eb4ab4c57`; source/test changes and current inventory hashes recorded separately.
- **Named procedure:** `CredentialRepositoryImplTest.concurrent cold flow collectors keep independent credential and query owners`; `CredentialRepositoryImplTest.CredentialManagementTests.search erases transferred credential when downstream rejects emission`; complete `:feature:fido2:testAndroidHostTest`; `:feature:fido2:ktlintCheck`.
- **Environment:** Windows host; Gradle 9.6.0; JDK 25; synthetic credential/query owners and mocked DAO rows.
- **Expected and observed:** Two overlapping cold-flow collections each hydrate a distinct credential owner. Cancelling the first while its downstream collector is suspended before accepting the emission erases that first owner, leaves the second credential readable, and leaves the shared borrowed query readable. The second consumer then erases its credential before completing; its query remains caller-owned until collection ends. The focused repository reports pass 48/48 cases (outer class 9, nested class 39). The full FIDO Android host suite passes 1,316 tests across 172 XML reports with zero failures/errors/skips; FIDO KtLint passes.
- **Limitations:** This proves host ownership for the named synthetic collectors. It does not prove every app collector joins before query erasure, successful renderer/ViewModel disposal in production, SQLDelight/native driver copies, provider retention, or heap-root absence. Existing source-row cleanup remains covered by separate DAO/repository owner regressions.
