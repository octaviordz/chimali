# Measurement Decision

Material questions include exact Kover toolchain compatibility, Kotlin filtering/denominator parity, report inventory fidelity and data/baseline continuity. Authoritative documentation and repository evidence do not resolve these fully.

A measurement is not warranted for the primary replacement question: Kover 0.9.11's Gradle plugin documentation already identifies missing required Android device-test collection. A host-only experiment could not establish complete eligibility. A separate device collection integration would be a custom hybrid integration outside scope and the hosted runner is waived. No present disposable device access or experiment budget was established. Kover with JaCoCo backend likewise has the documented plugin device limitation.

A targeted host-only test could answer limited counter questions, but without an owner-approved appetite and with no identified decision benefit after eligibility fails, it would not alter the recommendation. It is therefore omitted. Exact stack compatibility, counter parity, and maintenance/runtime costs remain unverified/unknown. This omission is recorded as an evaluation limitation, not a pass.
