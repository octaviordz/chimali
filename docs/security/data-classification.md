## 1. Governance Principles & Constraints

1. **Strict Secret Prohibition in Records**: This register and associated documentation MUST NEVER record actual secret values, recovery phrases, private keys, or identifying personal data.
2. **Volatile Plaintext Ownership**: All application-owned secrets (passwords, notes, payment info, mnemonics, seeds, private keys) MUST reside in volatile mutable structures (`CharArray`, `ByteArray`, `ErasableCharBuffer`).
3. **Public Metadata vs. Privacy Association**: Public derivation metadata (e.g., public keys, COSE algorithm identifiers, `rpIdHash`, blind index search tokens) are non-secret cryptographic parameters, but their association with specific user identities, account names, or relying party strings is privacy-sensitive. Public classification does NOT grant permission to log, retain, or disclose identifying metadata or blind index tokens.
4. **Unresolved Facts**: Unknown, unverified, or non-audited facts MUST be explicitly marked `Unresolved` with a reference to follow-up work in `specs/057-improve-verification-contracts/follow-ups.md`.
5. **Documentary Scope Limitation**: Consolidation of historical review records reconciles documented policy; it does NOT constitute a fresh application-wide source audit or runtime memory guarantee.
6. **Classification is Not Authorization**: Classifying a field as `Public Metadata` or `Private / Sensitive` defines its sensitivity tier; it DOES NOT constitute authorization to emit the field to logs, store it unencrypted, or bypass terminal cleanup obligations.

---

## 2. Classification Taxonomy

- **`Secret`**: High-impact cryptographic keys, seeds, passwords, and plaintext payloads. Unauthorized disclosure completely compromises cryptographic security or user account integrity.
- **`Private / Sensitive`**: User identity metadata, unencrypted item titles, and account associations that reveal user behavior or account ownership.
- **`Public Metadata`**: Cryptographic parameters, public keys, algorithm identifiers, and blind indexes required for protocol interop.
- **`Internal Operational`**: Nonce counters, sign counts, state machine flags, and memory management fences.
