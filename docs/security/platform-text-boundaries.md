## 1. Governance Principles & Strict Boundary Constraints

1. **Constitutional Mandate**: Per Constitution Principle I, immutable `String` references are strictly prohibited for application-owned secrets, and are permitted ONLY at audited platform input/rendering boundaries where mutable interfaces (`CharArray`, `ByteArray`, `ErasableCharBuffer`) do not exist.
2. **Absolute Exclusion**: **Cryptographic key material, seeds, normalization/serialization internals, cryptographic provider state, and diagnostic APIs NEVER qualify for the platform UI text exception.** Only genuine interactive platform input and rendering boundaries for user-managed non-seed secrets (e.g. vault item passwords in `BND-UI-001`, `BND-UI-002`) can be evaluated as permitted platform UI text exceptions under Constitution Principle I.
3. **Reviewer Provenance & Independence**: **Missing reviewer evidence remains missing; the consolidating author is not automatically the prior security reviewer.** Entries record original historical dispositions; consolidation does not confer fresh independent authorization.
4. **Findings vs. Permissions**: Unavoidable provider internals, native heap memory, JVM runtime copies, and diagnostic constraints are recorded strictly as **documented provider/runtime limitations or prohibited usages**, NEVER as approved platform UI text exemptions.
5. **Release & Isolation Controls**: Any platform string created at a permitted boundary MUST NOT become application state, cache, persistent data, or diagnostic output, and MUST be released immediately upon termination of the platform interaction.

## 3. Findings, Noncompliance & Residual Limitations Summary

1. **Non-Erasable Platform & Provider Copies**: Some application-owned buffers are explicitly zeroed in `finally` blocks; this historical register does not establish that every owner and terminal path has been audited. Memory retained internally by Android platform APIs (Compose layout caches, ICU normalizer heap, JCA `KeyFactory`, Bouncy Castle `BCMLDSAPrivateKey`, system clipboard listeners) cannot be reached or erased by user-space code.
2. **Device Clipboard Acceptance**: Current host tests exercise fixed 30-second scheduling and the `IS_SENSITIVE` flag; end-to-end device confirmation remains tracked as an open follow-up (`FUP-SEC-001`).
3. **Live Source Audit Gate**: This register consolidates historical evidence from 2026-09-09 and 2026-10-14..16 reviews. Current release branch static and runtime audit is tracked under `FUP-SEC-001`.
4. **Boundary Distinction & No Inferred Exception**: Cryptographic material (BIP39 mnemonic, root PRK, derived private keys, intermediate factors), normalization buffers, cryptographic providers, and diagnostic APIs do NOT acquire platform UI text permissions. Only user interactive password input and clipboard transfer (`BND-UI-001`, `BND-UI-002`) are permitted platform UI text boundaries under Constitution Principle I. All other entries document non-erasable provider/runtime limitations or diagnostic redaction controls.
5. **Current clipboard assessment**: The `BND-UI-002` timer is an in-process coroutine. Process death, scheduler delay or platform refusal can prevent or delay cleanup; the policy promises a best-effort scheduled attempt, not an unconditional expiry. Host tests do not establish device removal or preview behavior. The adapter still crosses Android's immutable text boundary. Neither implementation nor the current policy changes the historical reviewer disposition or grants a new exception. See [partial audit](secret-cleanup-audit-2026-11-13.md).
6. **Current diagnostic assessment**: The `BND-ERR-001` scrubber is heuristic and does not establish that all messages contain only fixed labels. Feature 065 has corrected selected source emissions, including the remaining reviewed `CredentialEncryptionService` exception/cause and RP-ID paths (SEC065-LOG-017), plus synthetic throwable-frame retention in the reviewed FIDO writers and fixed-message handling for HID channel identifiers in protocol errors (SEC065-ERR-007). `BaselineMeasurements` now accepts only the fixed `LatencyOperation` enum for its direct Android timing output; its synthetic host capture verifies the operation label and closed input surface (SEC065-CORE-021). This source/host result does not verify the final Android destination or other direct logging paths. The complete source-to-destination audit remains open; see the [Feature 065 assessment](../../specs/065-security-secret-cleanup/assessment.md) and [evidence index](../../specs/065-security-secret-cleanup/evidence/index.md).

**FIDO writer startup ordering (2026-11-16, partial):** `ChimaliApplication` installs FIDO Kermit writers before launching asynchronous transport-preference loading, closing the explicit startup race that could otherwise send an early preference diagnostic to Kermit's default writer (SEC065-LOG-053). This source order does not certify all initialization emissions or runtime destinations; the full matrix remains open under T029/T034/T035.

**Current clipboard policy (2026-11-13)**: The owner-authorized [NFR-SEC-050 revision](../brd.md) requires best-effort explicit clearing scheduled after 30 seconds, with execution/observation limits and failures handled without a guaranteed-removal claim. BND-UI-002 retains its historical reviewer provenance; the policy decision grants no new text-boundary permission or erasure assurance. Runtime acceptance remains pending.

**Automatic cleanup clarification (2026-11-13)**: The owner also selected a readable ownership check before automatic clearing, with a recorded skip for different or unreadable ownership. The remaining race with another app between checking and clearing is explicitly accepted; no atomic preservation guarantee is made. Explicit user-requested clearing remains separate. See [Feature 065 decisions](../../specs/065-security-secret-cleanup/spec.md#clarifications).

**Current timeout and sensitive-preview requirement (2026-11-13)**: The owner shortened the schedule to 30 seconds. Before publishing every sensitive Android clip, set `ClipDescription.EXTRA_IS_SENSITIVE=true` (equivalent key `android.content.extra.IS_SENSITIVE`) in its description extras. The current adapter already sets the equivalent key before `setPrimaryClip`; the existing host test checks the flag. This source observation is not fresh device evidence. The flag requests preview masking on supporting implementations and does not guarantee access restriction, expiry or history erasure. Historical BND-UI-002 timing/reviewer evidence remains unchanged.

**Current implementation reconciliation (2026-11-14, partial)**: Focused ownership tests found and corrected cleanup of mutable lookup-token and encrypted-metadata arrays attached to passkey projection rows (SEC065-DB-001) and consent RP lookup-token arrays (SEC065-DB-002). CTAP response owners are now erased after HID framing and BLE notification handoff (SEC065-CTAP-003, SEC065-BLE-001), and unexpected BLE CTAP and per-request CTAPHID exceptions are no longer forwarded to diagnostic writers (SEC065-LOG-021/022). These host results do not establish cleanup of SQL driver/generated copies, Android Bluetooth/HID stack copies or immutable database/model strings. Clipboard source behavior and diagnostic changes likewise remain subject to the open device, heap and configured-destination evidence in Feature 065; no runtime or release guarantee is implied by these host results.
**Vault list renderer owner synchronization (2026-11-16):** SEC065-VAULT-012 names `VaultListScreen`/`VaultItemRow` as the BND-UI-005 list-title/label boundary. The source receives borrowed ViewModel list values and creates immutable Compose text; renderer, semantics, accessibility and heap behavior remain Unverified.

**FIDO paired-device UI lifecycle boundary (2026-11-16):** BND-UI-007 covers the connected-host title; BND-UI-008 covers paired-device list aliases/names and removal snackbar text. `Fido2HomeScreen` collects identifier-bearing state only while `STARTED` and resets Compose state to safe stopped values. `PairedDevicesSection` cancels the removal snackbar on stop and restores the pending removal. This bounds app-owned UI state and event collection; Compose, renderer, accessibility and immutable `String` snapshots remain runtime/GC-managed and are not claimed erased (SEC065-FIDO-013).


**Development mnemonic QR acquisition (2026-11-16):** `BND-UI-003` covers Compose mnemonic reveal and manual recovery input; it does not authorize a new immutable-string exception for CameraX or ML Kit. The debug development scanner receives ML Kit `Barcode.rawValue` as an immutable `String`, then transfers a trimmed mutable array to the seed-import ViewModel. Provider/frame lifetime remains unverified and the exact owner path is recorded in Feature 065 SEC065-KEY-QR-001.
