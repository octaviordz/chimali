# Changelog - 2026-04-21 (FIDO2 Database Stability and RS256 Support)

## Overview
This update focuses on stabilizing the FIDO2 database persistence layer, resolving build-time JVM target inconsistencies, and adding support for RSA-based credentials (RS256) which were causing runtime validation crashes.

## Changes

### 1. FIDO2 Database Persistence & Stability
- **Atomic UPSERT Implementation**: Refactored `RelyingParty` insertion to use SQLite's `ON CONFLICT(id) DO UPDATE SET` syntax. This resolves the `SQLiteConstraintException` that occurred when re-registering with the same Relying Party ID.
- **SQLDelight Dialect Upgrade**: Migrated to `sqlite-3-38-dialect` to enable modern SQLite features like atomic UPSERT.
- **DAO Cleanup & Restoration**: 
    - Restored `getChangesCount` in `PasskeyCredentialDao` to fix functional regressions in credential deletion.
    - Removed redundant `CredentialStatistics` from the DAO layer to eliminate type ambiguity with the richer Domain-layer statistics model.

### 2. COSE Algorithm Support (RS256)
- **RS256 Support**: Added support for the `COSE_RS256` (-257) algorithm (RSASSA-PKCS1-v1_5 with SHA-256) in the `PasskeyCredential` domain model.
- **Validation Fix**: Updated the credential validator to accept RS256, preventing `IllegalArgumentException` crashes when loading passkeys generated by authenticators using RSA keys (e.g., Windows Hello or some platform authenticators).

### 3. Build & Infrastructure
- **JVM Target Alignment**: Explicitly set `jvmTarget` to `JVM_17` for the `androidTarget` in the Kotlin Multiplatform configuration. This resolves "Inconsistent JVM Target Compatibility" errors between Kotlin and Java compilation tasks.
- **Gradle Configuration**: Fixed the `sqldelight` block configuration by relocating it to the top level and using string-based artifact lookups for the dialect to bypass Gradle DSL accessor limitations with numeric segments.

### 4. UI Bug Fixes
- **Passkey Details Navigation**: Fixed a bug where the "Close" button in the Passkey Details screen was unresponsive. Updated the `CredentialManagementViewModel` to correctly clear the `selectedCredential` state upon dismissal.
