# Changelog: FIDO2 Ed25519 Support and ML-DSA-65 ID Correction

**Date**: 2026-03-26  
**Status**: Implemented  
**Feature Branch**: `004-fido2-hid`

## Summary
Successfully implemented support for the **Ed25519** signature algorithm (COSE -19) using **BouncyCastle 1.80** to ensure cross-platform consistency and bypass native Android KeyStore limitations. Additionally, corrected the **ML-DSA-65** COSE identifier from the experimental `-257` to the draft standard `-49`.

## Changes

### Ed25519 Support
- **Deterministic Key Derivation**: Implemented software-based Ed25519 key derivation in `Fido2CryptoService.kt`. Keys are derived from a `SHA-512` hash of the user's `MasterSeed` + `credentialId` + `"Ed25519"`, satisfying the deterministic backup requirement (FR-AUTH-030).
- **Lightweight Signing**: Integrated BouncyCastle's `Ed25519Signer` for performant signatures without system-level dependencies.
- **CBOR OKP Encoding**: Added native Octet Key Pair (OKP) encoding for Ed25519 public keys in `CborCodec.kt`, following the FIDO2/WebAuthn standard (kty=1, alg=-19, crv=6).
- **Validation & Factory**: Updated `AttestationObject.kt`, `PasskeyCredential.kt`, and `PublicKeyCredentialParameters.kt` to formally support and validate the `-19` identifier.

### ML-DSA-65 ID Correction
- **Standard Alignment**: Updated the COSE identifier for ML-DSA-65 from `-257` to `-49` across `Fido2CryptoService.kt`, `AttestationObject.kt`, `CborCodec.kt`, and `PasskeyCredential.kt`. 
- **Conflict Resolution**: This change resolves the collision with the `RS256` identifier (`-257`) in the IANA registry.

### Developer UX
- **Algorithm Selection**: Expanded the `DevelopmentToolsScreen.kt` to allow designers and testers to explicitly trigger Ed25519 registration flows alongside ES256 and ML-DSA-65.

## Verification
- **Compilation**: Verified successful compilation of the `:feature:fido2` module.
- **Validation**: Verified that the `-19` algorithm passes all domain-level validation checks in `PasskeyCredential` and `AttestationObject`.
